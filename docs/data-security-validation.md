# 数据安全插件源码验证记录

## 2026-09-25 手工验收反馈修复

此前的单元验证未覆盖“显示层还原 → 界面终态匹配 → 保存队列 → 重启”的组合，不能据此认定完整产品流程通过。手工验收发现的保存失败已追到原文/显示副本匹配：`_final_assistant_for_content` 比较模型令牌正文与还原后的显示正文，未命中规范消息后进入不适用的回退身份路径，终态保存提前返回。

本次修复：

- 终态匹配使用已保存的显示副本，保存与模型回放仍保留规范原文；匹配异常也先将已生成消息提交恢复保存路径，不再仅留在气泡内。
- 复杂参数进入原文重生成时，在“未执行”的工具反馈中提供本会话已知令牌的原值参考；不直接替换 Shell、代码和补丁。再次无法还原时，解释性结果有稳定的展示消息身份并可保存，不进入模型原生回放。
- 凭证提醒与令牌化状态直接显示在对话内，使用独立提示，不覆盖保存失败；一般成功状态不能盖掉同轮凭证提醒。设置明确手机号/邮箱不会触发凭证提醒。
- 类别校验移至类别区域上方，独立错误样式；保存失败时滚动定位，输入保留。
- 增加只读恢复脚本 `scripts/recover_security_history.py`：校验运行记录 checksum，导出独立恢复副本，不覆盖现有会话、不撤销历史编辑。

针对性测试：核心 13 项、集成 8 项、设置/提示/持久化 8 项通过，包括真实 SQLite 保存与重开、保存队列、成功写入但未收到确认时重启恢复、终态显示匹配、提示互不覆盖、类别提示可见和二次未知令牌不执行。Agent bootstrap 14 项通过。

完整 MainWindow 的 offscreen 测试在本机 Python 3.14 / PySide6 初始化信号连接时发生原生访问异常，未进入本次业务路径；不将该检查宣称通过。上述测试使用真实终态匹配方法、保存队列、恢复日志和 SQLite 单独验证关联边界，真实模型/完整桌面流程仍需手工复验。未执行打包验证。

复验凭证提醒可在保存设置后新建任务发送合成值：`API_KEY=sk-test-not-a-real-secret-12345678`。预期出现“疑似凭证”提示且请求继续；单发手机号或邮箱不触发此开关。

## 性能实测

本地 SDK 发送前的请求转换；引擎预热后 40 个不同文本样本，包含邮箱、手机号和普通文本。映射使用真实 Windows DPAPI；不计模型网络耗时、后台凭证扫描和异步日志写入耗时。提醒列统计的是请求线程增加的同步时间。

| 配置 | 100 KiB p95 | 1 MiB p95 |
| --- | ---: | ---: |
| 全部关闭 | 0.0002 ms | 0.0009 ms |
| 仅凭证提醒 | 0.1654 ms | 1.5843 ms |
| 邮箱、手机号令牌化 | 3.0102 ms | 24.4248 ms |
| 八类全部开启 | 8.8984 ms | 79.8416 ms |

以上样本达到同步提醒 ≤ 5 ms、令牌化 100 KiB ≤ 20 ms / 1 MiB ≤ 100 ms 的目标。八类开启时缓存命中的 1 MiB p95 为 1.1527 ms。关闭时结果为原请求对象，未加载引擎或创建存储；这里是插件入口微基准，不宣称测量了整个应用启动或网络链路。

## 产品验收建议

1. 默认关闭发送普通消息、附件并运行工具，确认模型调用次数、授权和正常鉴权不受影响。
2. 单独开启一项，再开启令牌化并仅选邮箱，检查用户原文仍在、本轮提醒可理解，AI 新生成内容不被扫描。
3. 用客户表分析、邮箱查询、IP 诊断、代码与补丁任务检查稳定令牌及必要时的原文继续提示。
4. 切换会话、追加输入、停止和重试、关闭插件后重开历史，检查不串映射、不丢消息、不重复副作用。
5. 验收包内插件资源、正常加载、缺失/失败状态、主题预览及实际 Windows 缩放环境。
