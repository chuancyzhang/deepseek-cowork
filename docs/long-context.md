# 超长上下文（实验功能）

超长上下文让桌面主会话在多个模型上下文窗口之间继续任务。完整消息和工具结果保留在会话历史中；模型接近当前工作集上限时，应用保存任务检查点，再继续执行。

## 启用与容量

进入“设置 → 实验功能 → 超长上下文”。默认关闭，默认档位为 **300k tokens**，也可选择 **1m tokens**。未启用时点击“启用”，已经启用时修改档位后点击“应用设置”。设置重启后保留，从下一次启动的任务轮次生效；正在运行的任务保持原设置。

![超长上下文设置](images/long-context/settings.png)

档位表示目标输入上限。实际输入上限为：

```text
min(目标上限, 模型容量 − 输出预留 − 安全余量)
```

应用通常在有效上限的 80% 附近整理上下文；较小窗口会提前预留检查点空间。选择 1m 不会增加模型本身的容量。输出预留默认 8192 tokens，安全余量取模型容量的 5% 与 2048 tokens 中的较大值。

应用仅对适用的已知官方模型使用项目已有容量定义。其他模型需要在“模型与服务 → 编辑模型”填写“上下文容量（tokens）”，也可填写“输出预留（tokens）”。未知容量不会被猜成 128k 或 1m。

关闭后保留历史和检查点，下一轮恢复完整历史路径。完整历史超出已知模型容量时，应用提示重新启用或新建会话。

## 查看当前工作集

点击对话里的“用量”按钮。“当前上下文”显示输入工作集的估算占用，包括系统提示、工具定义、检查点、消息和协议回放；下面的累计用量继续表示服务返回的计费用量。

![当前上下文与累计用量分开显示](images/long-context/usage.png)

- 容量条表示已用和剩余，组成条表示各类内容的占比。
- 分母低于所选目标时会显示容量限制原因；未知读数显示“待统计”或“暂不可用”。
- 运行中修改设置会提示“新设置下一轮生效”。重开历史展示最近快照并标注“上次运行”，不会为了刷新数字发起模型请求。
- 压缩提交成功后才更新为新窗口用量；整理请求的用量计入当前任务账单，不会覆盖主任务工作集快照。

这些数值是上下文估算，并会根据主任务实际输入用量向上校正。已支持计量规则的图片按模型、尺寸和实际发送精度计入预算，包含用户图片和网页观察截图。图片不会因启用超长上下文而被统一拦截。

没有计量规则的图片直接跳过本地估算，文本继续正常统计和压缩，图片仍按原流程发送和保存。“当前上下文”会注明未计入的图片数量；这种情况下显示的数字不代表完整输入用量，实际容量仍由模型服务校验。远程图片不为估算而额外下载；其他尚未支持的附件类型仍可先用工具读取有界正文。

![未计量图片的上下文说明](images/long-context/image-budget.png)

## 压缩、停止与恢复

真正开始整理时，对话中会出现细分隔线提示。同一次整理在原位置更新成功、失败或停止状态。提示不进入消息账本，也不会发送给模型或出现在历史检索结果中。

![压缩失败与重试入口](images/long-context/compression-failed.png)

整理使用当前模型的独立无工具请求，因此会产生额外计费用量。旧历史超长时会分段整理，并显示当前段数；正文上限为约 4096 tokens，格式或引用不合格时只自动修复一次。

失败后保留旧窗口、输入和已有成果，任务等待明确操作。点击“重试压缩”沿用同一次运行，不重复提交用户消息或执行已有工具；也可使用现有停止入口。若提示当前输入或必要片段太大，请先停止，缩小材料后重新开始；运行中改变容量不会改变当前冻结预算。

提交前崩溃仍使用旧窗口，提交后恢复已保存的新窗口。打开历史不会自动执行。编辑历史会使受影响的检查点及后续窗口失效；新分支建立自己的窗口，不继承原会话窗口指针。

## 范围与历史查询

首版用于桌面主会话，包括旧会话续聊。企业消息、定时任务（包括手动运行计划）、子 Agent 和使用独立材料集的内部文件转换保持原路径。

启用后的主会话可使用 `history_search`、`history_read` 查找本会话的早期证据。查询前先由当前运行确认相关历史已保存，再启动后台查询，因此也能读取同一任务刚完成的工具结果。查询绑定当前会话：搜索最多返回 20 条、每条 600 字符，并限制 SQL 执行时间；读取默认每页 6000 字符、最多 12000 字符。支持中文子串匹配，不返回原始 reasoning。

大工具结果先完整保存，再以固定摘录和消息引用进入工作集。检查点只承担交接作用：不恢复旧授权，不把未知结果视为成功。是否执行过操作仍以现有运行日志为准。

窗口内继续执行严格追加校验；只有成功提交新窗口才能重置校验基线。切换时可能降低一次缓存命中，随后重新积累稳定前缀。

实现和实测记录见[超长上下文验证](long-context-validation.md)。
