# DeepSeek Cowork 5.1.0 发布说明

> 发布版本：**5.1.0** · GitHub 标签：`v5.1.0` · 变更范围：`2026-07-29`—`2026-08-01`

5.1.0 的重点不是增加一串孤立入口，而是把“找到能力、完成任务、修订结果、恢复
过程”连成更清晰的桌面工作流。相较 5.0.9，本版集中交付六条主线。

## 发布摘要

1. **能力从技术清单变成任务入口**：AI 能力商城、新对话首页与浏览器设置统一围绕用户要完成的工作。
2. **生成文件可以在应用内安全修订**：新增多格式编辑、兼容预检、冲突检测、上一版备份与原子保存。
3. **附件、历史与任务状态更连贯**：支持粘贴文件、图片放大、分组分页和更可靠的历史恢复。
4. **企业消息扩展到五个渠道**：新增 QQ、微信扫码接入，并统一单活动渠道与交付边界。
5. **模型调用契约面向下一阶段收敛**：补齐 DeepSeek Responses 回放与服务端搜索，核心 Tool 直出，文本写入统一为完整读取与审计补丁。
6. **源码态与发行包行为对齐**：隔离外部浏览器进程，构建时强制收集动态 Skill 的核心依赖。

## 1. 任务驱动的能力入口

### AI 能力商城

- 普通视图按“查找资料、处理文档、分析数据、制作内容、金融研究”组织能力。
- 每张卡片先说明用途和典型任务，再提供“开启 / 设置后开启 / 已开启 / 关闭”。
- Tool、Script、MCP、依赖、文件和调试集中到“高级管理”，仍保持可见直达。
- “我的能力”单独容纳用户创建、导入或 AI 生成的 Skill，不强行套用官方分类。
- 配置保存失败时保留输入与错误，不会在失败后误显示为已开启。

### 新对话首页

- “PPT Agent”直接进入 PPT Mode。
- “进行金融分析”在万得与东方财富妙想均已启用且配置就绪时一起加入能力；否则明确列出缺项。
- “数据分析”以当前工作区为数据边界，引导统计、可视化和机器学习任务。
- “浏览器自动化”只在能力与扩展连接均就绪时加入会话；否则引导回能力商城设置。

这些卡片只准备提示词和能力，不会自动发送、安装组件或修改外部数据。

### 浏览器自动化

- 本地文件准备、Chrome/Edge 扩展安装、连接检查、真实标签页探测和 Skill 启用进入同一流程。
- 只有 CLI 校验、扩展连接和执行探测都通过时，商城才显示“已开启”。
- BrowserSkill CLI 作为应用数据目录中的外部程序启动，不再继承 PyInstaller `_internal` 的 DLL 搜索环境，避免运行库冲突和旧发行目录被占用。
- BrowserSkill CLI 0.1.8 与扩展 0.1.4 随发布包提供，运行时不再下载 GitHub 制品；离线加载为主入口，同时保留 Chrome Web Store。
- Cowork 只负责校验、解压、打开 Chrome/Edge 扩展页与目录并检查连接，不会静默安装扩展。

## 2. 文件、附件与交付物

### 粘贴与图片查看

- 从 Windows 文件管理器复制的一个或多个文件可以直接粘贴到输入区。
- 本地文件优先走统一附件管线；文件夹、失效路径和不支持项会明确提示。
- 剪贴板位图保存为会话托管 PNG；图片附件支持点击或键盘打开大图预览。
- 预览提供适应窗口、100%、按钮与 `Ctrl + 滚轮` 缩放，范围为 25%—400%。

### 内嵌安全编辑

| 格式 | 当前支持 |
| --- | --- |
| DOCX | 正文、常用段落/列表/表格/图片；安全条件下原样保留普通页眉页脚 |
| XLSX | 多工作表、值、公式、常用格式、合并单元格和行列操作 |
| HTML | 隔离编辑静态 body，原始 head 保持权威，脚本不执行 |
| CSV/TSV | 表格编辑与往返校验 |
| Markdown/JSON/XML/YAML/文本 | 文本编辑；结构化格式保存前严格解析 |

PDF、PPTX、图片、旧版 Office 和包含修订、复杂域、嵌入对象、图表、数据透视表、
外部链接等高风险结构的文件继续只读。

保存链路统一为：

1. 进入编辑前执行格式、结构、大小和资源预算预检。
2. 保存前重新计算源文件 SHA-256，外部修改会阻止覆盖。
3. 临时文件完成解析验证后，保存唯一上一版备份。
4. 通过原子替换覆盖源文件；失败保留原文件、用户编辑和恢复入口。

DOCX/XLSX 编辑上限为 25 MiB，HTML、CSV/TSV 与普通文本为 10 MiB；超限或复杂
结构直接说明阻断原因，不降级到不受保护的写入。

## 3. 历史、导航与反馈

- 项目历史默认显示最近 5 个会话并按 5 个扩展；独立聊天默认显示 3 个并按 3 个扩展。
- 正在运行或等待输入的会话始终保留在侧栏，不占普通分页批次。
- 长历史优先展示最终回答，thinking、Tool 和阶段回复在用户展开后按需物化。
- 消息规范化后重新计算渲染区间，避免历史回复因旧索引区间而丢失。
- UI 保存队列与 daemon 共用同一持久化过滤规则，运行时 Skill 上下文不进入长期历史。
- 应用内 Toast 移到主内容区右上方，最多显示三条并避开 Windows 原生窗口按钮；系统通知不再携带版本或设备后缀。

## 4. 企业消息

- 企业消息页统一展示飞书、钉钉、企业微信、QQ 和微信；同一时间只运行一个渠道。
- 切换渠道只改变活动标记，不删除其他渠道已保存的连接信息。
- 飞书、QQ、微信共用扫码窗口，覆盖生成、等待、已扫码、手机确认、配对码、过期、失败、取消和重新生成。
- QQ 支持私聊和群聊中 @ 机器人；微信首版支持私聊。两者处理文字与链接，不支持的媒体会收到明确提示。
- 飞书可原生发送本地文件、图片和链接；钉钉/企业微信只发送可访问 URL；QQ/微信不暴露附件发布 Tool。
- 二维码、Secret、Token、OpenID 和用户标识在诊断日志中统一脱敏。

## 5. 后训练调用偏好与 DeepSeek Responses 协议兼容

这部分是 5.1.0 的底层主线：为 DeepSeek V4 Flash 正式版及后续 V4 Pro 正式版
的**后训练调用偏好和 Responses 协议兼容**做准备。

### Responses 协议

- 官方 DeepSeek Responses 会保存并按原顺序回放 `reasoning`、`message`、`function_call` 与 `web_search_call`。
- 旧历史中的 reasoning 会转换为标准内容块；缺少必要推理或函数结果时直接给出恢复错误，不裁剪历史继续。
- 请求自动提供并去重服务端 `web_search`；搜索状态与失败原因进入任务观测，不进入本地函数 Tool 执行器。
- 官方 DeepSeek Responses 使用服务端上下文管理，不发送标准 OpenAI Responses 的 `prompt_cache_key`。
- 兼容逻辑只在官方 DeepSeek 地址与 Responses 协议同时成立时启用，不影响其他 OpenAI-compatible 服务。

### 能力暴露

- `skills/` 中符合当前上下文的核心内置 Tool 首轮直接可见，不再要求模型先搜索基础能力。
- 会话明确指定的可选能力同步直出；其他已启用可选能力、用户扩展和 MCP 继续由 `tool_search` 按需发现。
- 指定能力选择器只显示可选能力、MCP 和自定义能力，不重复展示始终生效的内置 Tool。
- 工作区尚未绑定时，文件与命令 Tool 仍保持 Schema 可见；实际调用明确返回 `workspace_not_selected`。
- 任务观测记录 Tool 来自核心直出、会话指定还是搜索发现，集合未变化时不重复刷屏。

这些变化同时缩短了模型的基础 Tool 选择路径，并让 Responses 多轮回放拥有更稳定
的动作与结果对应关系。

## 6. 统一文本工具与补丁审计

普通文本接口收敛为四个明确职责：`glob` 发现路径，`grep` 定位内容，
`text_file_read` 完整读取，`apply_patch` 提交变更。

### 完整读取

- 严格处理 BOM、UTF-8 和显式编码；无法解码时报告原因。
- 只有完整读取建立 SHA-256、字节数、编码、BOM 和换行风格凭据。
- 后续写入以内容哈希判断读取是否仍有效，不依赖时间戳猜测。

### 标准补丁

- `apply_patch(patch: string)` 在 OpenAI-compatible、DeepSeek 和 Anthropic 中使用同一函数 Schema。
- 支持普通文本 Add、Update、Move 和 Delete；输入上限 12 MiB，单次最多 100 个文件。
- hunk 必须唯一且逐字符精确匹配；Office/PDF 在预检阶段拒绝。
- 路径同时检查词法路径、`realpath`、重解析点和 UNC，防止工作区逃逸。
- 全量预检失败或删除未获确认时保证零修改；运行期 I/O 失败明确返回 `partial_apply`。
- 诊断覆盖 `start/preflight/confirm/commit/finish/error`，但不记录文件内容或补丁正文。

这套接口减少了同义文件 Tool 和模糊写入路径，为模型后训练中的调用偏好提供稳定
名称、参数和失败语义，也使本地修改更容易审计。

## 7. 打包与运行时一致性

- 冻结构建从 `sys._MEIPASS` 读取随包编辑器和能力资源，不把 EXE 同级目录误作只读资源根。
- 构建 spec 扫描 `skills/` 与 `ai_skills/` 中动态 `impl.py` 的直接 `core.*` 导入，统一加入 hidden imports。
- 动态依赖解析失败或核心工作区模块缺失会直接中止构建，避免源码可用而发行包整组 Tool 消失。
- 离线编辑器不携带 Node 运行时、`node_modules`、源码映射或 CDN 依赖；许可证和资源体积继续受发布门禁审计。

## 升级说明

- 当前应用版本必须显示 `5.1.0`，GitHub Release 标签使用 `v5.1.0`。
- 现有会话、项目、模型渠道、Skill 配置和企业消息凭据沿用原存储，不需要手工迁移。
- 第一次进入某类编辑器时才加载对应离线资源；普通启动不会初始化 Office 文档模型。
- 浏览器扩展仍需要用户在 Chrome 或 Edge 中确认安装，应用不能代替商店授权。
- 微信与 QQ 当前的媒体和附件边界不会因升级自动扩大。

## 发布验收清单

### P0：必须通过

1. 运行文档链接、版本和截图契约检查。
2. 执行完整自动化测试，确认版本断言与 `APP_VERSION` 一致。
3. 使用正式 `.venv` 完成干净 PyInstaller 构建和 `package_release.py` 审计。
4. 在冻结包首轮确认核心文件/命令 Tool 可见，并完成读取与补丁往返。
5. 使用官方 DeepSeek Responses 完成“reasoning → Tool → 结果 → 下一轮”及服务端搜索验证。
6. 分别保存普通文本、HTML、DOCX 和 XLSX；验证冲突、上一版恢复和失败不覆盖原文件。

### P1：代表性流程

1. 从文件管理器粘贴多文件，并打开图片大图预览。
2. 检查项目/独立聊天分页、后台运行状态和长历史按需展开。
3. 完成浏览器自动化的准备、扩展连接、标签页探测与启用。
4. 检查五个企业消息渠道的配置保留和单活动切换；至少验证一个扫码渠道。
5. 在 100%、125% 和 150% Windows 缩放下检查编辑器、扫码窗口和关键操作。
