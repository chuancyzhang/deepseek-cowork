# 仓库维护与产物管理规范

目标：优先更新已有内容，隔离临时产物，及时清理失效资源，避免每次 AI 修改都留下重复文件和额外机制。

## 修改约束

1. **优先更新现有文件。** 文档、脚本、测试先查找并复用现有入口；只有现有文件无法合理承载、且用途明确时才新增，不为每次改动另建一套。
2. **临时产物统一隔离。** 开发、调试与验证产生的脚本、日志、截图、中间产物和隔离测试数据，统一放在仓库根目录 `.tmp/<任务名>/`。工具输出参数及进程级 `TEMP` / `TMP` 等临时目录配置也应指向该目录，不散落到其他位置。`.tmp/` 必须被 Git 忽略，不得暂存、提交或强制添加；正式交付物和确需保留的验证材料按既有目录规范存放。
3. **不默认生成过程档案。** 除用户明确要求外，验证结果在回复中说明，不新建每次任务的报告、验收记录或清理流水。可复用经验更新已有本地笔记，不重复追加已经覆盖的内容。
4. **测试使用最小有效夹具。** 优先动态生成图片、PDF、PPTX 等样例并写入任务临时目录，不依赖过时界面截图或个人文件。保留有效回归覆盖，不通过削弱断言或掩盖产品缺陷完成清理。
5. **正式资源只留必要内容。** 文档截图应服务操作说明，同场景尽量复用。替换内容时同步清理失效的旧图、旧描述和引用；删除前核对应用、测试和打包依赖，不因历史引用而保留无用资源。
6. **修复不堆机制。** 优先纠正现有流程，避免随手新增状态、持久化标志、回退路径或重复实现。新机制必须有明确必要性，不能仅为通过测试而添加；对话改动仍以消息可靠、过程连续、会话隔离、失败可恢复、用户可控制为准。

## 收尾检查

- 新增文件是否必要，是否可以并入现有入口。
- 被替代的旧文件是否仍有用途，引用和依赖是否完整。
- 本次产生且后续无用的临时文件是否已清理；仅清理确认由本次任务创建的内容，保留交付物及仍有用途的验证材料。
- Git 差异中是否混入临时产物、个人数据或无关改动。
