# Cowork UI/UX 规范

维护日期：2026-11-14。用途：供后续 AI 和开发者设计、修改、评审 Cowork 界面时复用。

核心方向：**以任务为中心、对话优先、灰白柔和、信息清晰、操作可控、失败可恢复。** 评价顺序是用户能否理解并完成任务、能否恢复、操作是否顺畅，最后才是视觉表现。

## 1. 使用方式与依据

开始设计前，明确用户是谁、要完成什么、已有多少背景知识、最大的阻碍是什么，以及本次改动的范围和验收标准。结合现有页面和组件决定实现方式，不先设计容器再填功能。

本文件包含两类内容：产品与交互约束，以及核对日期当天的默认视觉参数。参数是源码快照，不是独立的配置来源；实现时读取当前 token 和用户生效的主题，不能把表中的颜色、尺寸再次硬编码进页面。

依据与职责：

| 依据 | 用途 |
| --- | --- |
| [AGENTS.md](../AGENTS.md) | 项目约束、授权范围、实现及验收要求 |
| [对话第一性原则](CONVERSATION_FIRST_PRINCIPLES.md) | 消息可靠、过程连续、会话隔离、失败可恢复、用户可控制 |

本文件随仓库维护，集中记录可复用的视觉、交互和实现规则；验证结果在交付回复中说明，临时截图按仓库产物规范隔离。引用的必要文档应随仓库提供，不能依赖未提交的本地笔记。

## 2. 信息架构与任务路径

- 按用户完成任务的顺序组织页面，让用户通过布局和操作入口理解“这里能做什么、现在是什么状态、下一步做什么”，无需逐项添加说明文案。
- **让布局承担解释。** 优先通过位置、分组、对齐、间距和视觉层级表达关系。次要标签与描述只用于消除歧义、支持决策或解释必要限制，不复述标题、按钮和已经清楚呈现的内容。不要为每个区域默认添加副标题、说明或徽标。
- 字段用途、关键状态、错误原因、恢复入口和操作后果不能为了简洁而隐藏；必要信息不能只放进悬停提示，控件的可访问名称也应保留。
- 同一任务区域最多一个视觉主操作。常用操作直接可达，低频配置放在就近的菜单或折叠区。
- 状态、失败原因及恢复入口直接可见；原始参数、日志、代码和完整结果放入明确的详情视图，支持选择和复制。
- 管理页通过选中导航和内容布局标明位置，避免页名、分类名和正文大标题重复。仅展示所选消息渠道的配置，低频选项折叠，切换保留未保存输入。项目行新建和“…”按钮在悬停或键盘聚焦时显示；目录失效不阻止归档。归档项目及其聊天分组从常用列表和本地资料库收起，文件与聊天记录保留，在侧栏归档中恢复；汇总历史目录时排除已归档路径，不能重新生成该项目。
- 管理页左上角固定提供“返回聊天”，返回时保留原会话草稿与工作区状态。能力使用“技能／MCP 服务／专家／界面插件”横向导航，插件在同一内容区显示，不再另开带“返回能力”的页面；资料库用单行下拉选择来源，左侧只显示当前来源的项目或目录，右侧是文件列表；资料详情替换主内容区，返回时恢复列表位置，禁止追加在列表底部。本地资料库汇总项目文件，添加到聊天复用附件保存边界。
- 侧栏底部的能力、资料库、常用任务和团队空间保留两列入口；设置独立固定在最下方，使用带右箭头的整行按钮，悬停、焦点与当前页选中覆盖整行。
- 持久浏览、管理和配置使用路由页面；局部选择使用浮层；简短原子流程或必要确认使用对话框。同一功能不维护重复的页面和对话框流程。
- 相同概念使用一致的名称、位置和操作方式。界面文案使用简洁中文，协议与技术专名按需保留。
- 卡片只用于独立、可重复的对象，例如能力条目。一般页面使用标题、排版、间距和细分隔线建立层次，避免整页卡片套卡片。

## 3. 视觉风格与主题

默认风格是明亮、克制的中性工作台：白色内容区、浅灰导航、深灰主操作、轻边界、适度留白。用户选择其他内置主题、自定义主题或深色模式后，界面服从其配置。

不主动引入大面积紫蓝强调色、渐变、玻璃效果、厚重阴影、粗描边、过度圆角或无交互价值的动效。存在 `shadow_*`、`bg_glass` 等历史 token，不代表新页面必须使用这些效果。

### 3.1 默认浅色颜色

| 用途 | Token | 当前默认值 |
| --- | --- | --- |
| 主操作 | `primary` | `#404040` |
| 主操作悬停 / 按下 | `primary_hover` / `primary_pressed` | `#333333` / `#282828` |
| 主操作弱背景 / 焦点 | `primary_soft` / `primary_focus` | `#f0f0f0` / `#b8b8b8` |
| 主要文字 | `text_primary` | `#303030` |
| 次要文字 / 辅助文字 | `text_secondary` / `text_tertiary` | `#686868` / `#767676` |
| 反色文字 / 禁用文字 | `text_inverse` / `text_disabled` | `#ffffff` / `#a7a9af` |
| 应用底色 | `bg_app` | `#f8f8f8` |
| 主要内容 / 对话 | `bg_main` / `bg_chat` | `#ffffff` |
| 侧栏 | `bg_sidebar` | `#f6f6f6` |
| 次级背景 | `bg_secondary` | `#f5f5f5` |
| 用户消息 | `bg_user_bubble` | `#f3f3f3` |
| 悬停 / 侧栏选中 | `bg_hover` / `bg_sidebar_selected` | `#eeeeee` / `#eaeaea` |
| 普通边界 / 弱边界 | `border` / `border_subtle` | `#dedede` / `#e8e8e8` |
| 分隔线 | `separator` | `#e6e6e6` |
| 文字选区 | `selection_bg` / `selection_text` | `#d5d5d5` / `#242424` |
| 对话链接 | `chat_link` | `#1f5fa8` |

优先使用区域语义 token，例如 `composer_*`、`sidebar_*`、`right_sidebar_*`、`management_*`、`preview_shell_*`；默认颜色相同不等于可以互换。自定义主题可以分别设置这些区域。

成功、警告和错误使用 `success_*`、`warning_*`、`error_*`。状态必须同时有文字或图标，不能仅靠颜色区别。红色用于失败或危险动作，不用于普通强调。

### 3.2 默认深色参考

“简洁”深色主题当前使用应用底色 `#1b1b1b`、内容面板 `#242424`、侧栏 `#202020`、主文字 `#ededed`、次要文字 `#b3b3b3`、边界 `#404040`、悬停 `#303030`、主操作 `#d5d5d5`。按钮文字和图标使用主题的 `text_inverse`，不能固定为白色。

深色模式由主题系统统一解析，不在组件内部手工反转颜色。其他内置主题保留各自配色。

## 4. 字体、密度与几何

下列尺寸为默认逻辑像素，随 Chromium 设备缩放、主题阅读设置和字体配置适配，不是屏幕物理像素。

| 项目 | 当前基线与使用方式 |
| --- | --- |
| 界面字体 | 读取应用/主题字体；默认 `Microsoft YaHei UI` |
| 代码字体 | 读取主题等宽字体；默认 `Consolas` |
| 正文 | `font_size_body = 14` |
| 元信息 / 辅助说明 | `font_size_meta = 12` / `font_size_caption = 11`；不用于长篇正文 |
| 区块 / 页面标题 | `font_size_section = 16` / `font_size_page = 20` |
| 大标题 | 通用 `font_size_hero = 24`；当前首页标题使用局部 `28`，不推广到所有页面 |
| 字重 | 普通正文保持常规字重；强调优先 `500` 或 `600`，`700` 少量使用 |
| 间距 | 优先 `4 / 8 / 16 / 24 / 32 / 40`；复用现有组件的局部间距 |
| 圆角 | 小控件 `6`、常规 `8`、输入区与浮层通常 `10`；`14` 不作为所有容器的默认值 |
| 控件高度 | 小 `28`、默认 `32`、大 `36`；现有发送按钮保留 `34` 的局部尺寸 |
| 列表行高 | 紧凑 `36`，舒适 `44` |
| 图标 | 小 `14`、默认 `16`、大 `20`；优先现有图标与共享绘制函数 |
| 通用焦点边界 | `focus_ring_width = 2`，具体控件沿用已有焦点实现 |
| 用户消息内边距 | 水平 `16`，垂直 `12` |

保持文字可读、控件可点击。不能为了把所有控件放在一行而持续缩小字号和点击区域。长名称优先省略并提供完整提示；原始路径、错误详情和代码应能完整查看与复制。

## 5. 工作台布局

采用左侧导航、中间任务内容、右侧按需工作区的结构。标题和主要工具入口保持可达，右侧面板不得覆盖它们。

| 区域 | 当前几何基线 |
| --- | --- |
| 左侧栏 | 默认 `240`，范围 `204–320` |
| 对话列 | `conversation_preferred_width = 960`；当前配置上限 `1040`，实际宽度同时受可用空间与侧栏占位约束 |
| 消息内容 | `message_max_width = 880`；短消息按内容自然宽度展示 |
| 用户消息 | `user_bubble_max_width = 640` |
| 右侧面板 | 最小 `272`、首选最小 `360`、最大 `500`；基础宽度比例 `0.28` |
| 浮动文件目录 | 默认 `320`，最小 `240` |
| 普通管理内容 / 设置内容 | 最大宽度 token 分别为 `1080` / `1120` |

这里的宽度用于理解当前布局，不能给每个子控件设置相同固定宽度。复用已有宽度计算和布局入口，避免为一个页面另建一套相互竞争的尺寸规则。

### 5.1 首页

- 以任务标题和输入区建立开始路径。标题上方保留“从一个想法，开始今天的工作”，下方保留“整理资料、分析数据，或把一个想法做出来。”，与输入区左对齐，使用主题的次要文字样式。
- 首页输入框默认收紧留白，编辑区最小高度为 `70`，沿用现有按内容增高至 `240` 的机制；对话页仍为 `64–180`。尺寸为逻辑像素，默认输入框整体比原首页缩短约 20%，上下文标签和附件按实际内容继续占位。
- 输入区下方保留紧凑快捷入口和最近任务，低频主题、工具箱入口收进“工作台选项”。
- 首页与对话共用同一输入区，切换呈现不能丢失输入、附件或当前会话选择。
- 只打开而未使用的空白会话不进入侧栏和首页最近任务；默认模型、自动分配的工作目录、关闭的拷问模式及“待开始”状态不算任务内容。文字、附件、技能、专家、引用、手动命名和真实运行成果应保留，不能仅凭“零消息”隐藏。
- 未发送的实际草稿使用“草稿 · 内容摘要／已选内容”区分；正常退出和更新通过同一保存队列保留草稿。清空草稿后不能恢复旧输入，重复保存不能冒充新的对话活动。已有纯空白记录仅从快捷列表收起，保留管理入口。

### 5.2 对话

- 顶部显示对话标题，可直接点击改名；聚焦后支持 `F2`，`Enter` 保存、`Esc` 取消。失败保留原名称并说明原因。
- 对话标题与工作区标签栏齐顶，用量、搜索和历史提问并入标题行，不再额外占用消息区一行。长标题仅在绘制时省略，改名与可访问文本保持完整；打开工作区后，标题和工具所在区域同步预留面板宽度，不能被覆盖。
- 不重复显示“主对话”等无助于定位的标签。项目归属在确有任务价值的位置展示。
- 消息区独立滚动，输入区固定在底部。用户查看历史时，新输出不得强行夺走阅读位置；已有自动跟随规则保持一致。
- 打开历史时，正文视口显示与消息对齐的占位，首屏分批恢复完成、原有滚动位置应用后再移除；占位不参与消息布局，不额外延长加载时间。失败时退出占位并保留原因与重试入口，切换会话不让旧回调影响当前对话。
- 历史回复的过程入口优先显示已记录的整轮“用时”，不展示阶段与工具数量；缺少可信耗时的旧记录保留“执行过程”，不从消息时间或各阶段耗时推算。耗时只保存为会话展示元数据，思考原文、工具详情和各层折叠继续复用原实现。
- 用户消息使用轻灰背景；AI 正文以开放排版为主，避免为每段文字套卡片。正文、过程、文件与操作之间保持清楚层次。
- 左侧栏统一使用紧凑的 DeepSeek Cowork 品牌，原生窗口标题栏、首页与普通助手回复不重复显示品牌；应用菜单使用“应用”名称。专家回复显示对应轮次身份快照中的专家名称，不能随当前专家选择改写；嵌套正文、展开阶段及已有专家标题的子任务面板不重复显示身份。
- 思考过程沿轻量时间线排列，名称统一为“深度思考”。点击标题直接在原位置展开或收起原文，不再增加“查看原文”或“展开全文”入口；展开时按实际顺序追加流式内容。收起只影响原文显示，工具调用、状态和失败原因仍可查看；再次展开或停止后保留已收到的内容，支持完整复制。整轮过程折叠与单段原文折叠分开控制，最终回答保持可见。
- 工具名称或“详情”直接打开工作区“任务”标签中的该次调用，准确对应所属会话和工具调用；复用一个详情页，不另建弹窗。顶部返回调用记录，保留列表位置。
- 文件操作记录的路径使用 `chat_link` 颜色、下划线与加粗，点击打开右侧工作区的当前文件内容，多文件操作分别提供链接。相对路径绑定所属会话工作目录，不能随当前会话误定位；不存在的文件明确提示并保留已有预览，点击读取路径不登记为交付物。
- 历史消息阅读状态保持自然气泡宽度；编辑状态按可用宽度展开，窗口和主题变化时保持输入，窄宽下重排操作按钮。编辑区支持选择、拖入、粘贴文件和图片，长文本粘贴沿用聊天框阈值转为 TXT；附件可逐项移除，编辑草稿绑定原消息所属会话，与底部输入区独立。取消后恢复原文、附件和阅读尺寸，保存失败保留编辑内容，不改变历史替换的确认边界。
- 过程时间线按实际内容绘制节点：思考、阶段说明、工具使用各自对应的图标；没有思考原文时不制造“深度思考”标题。只显示已记录的耗时，未知时不显示 `0.0 秒`。工具标题、状态和详情同排，技术名称与目标路径另起一行，失败原因再单独换行，避免把全部信息挤进一行。
- AI 回复中已确认存在的工作目录文件在正文下显示紧凑文件列表，默认最多三行，更多内容按需展开；文件名与正文路径共用工作区打开入口。列表和路径链接仅属于显示投影，不写入模型历史；相对路径与绝对路径指向同一文件时复用标签并保留编辑草稿。
- 已发送附件、对话引用、技能／连接器与资料快照放在用户气泡顶部，用带图标的标签展示，多项自然换行。长文件名保留扩展名，完整名称与路径可访问；编辑消息时标签保持可见。查看发送时的引用快照与打开来源对话是不同操作；分支里的历史引用不能暗示已携带快照。
- 复制、重新生成、分支、更多操作使用紧凑图标入口，提供悬停说明、可访问名称和键盘可达性。
- 用户气泡仅包住正文与附件，操作行和时间位于气泡外，短文本不能被隐藏按钮撑宽撑高。消息时间默认隐藏，悬停消息或聚焦其操作时显示；AI 回复时间靠操作行右侧，触屏环境保持可见。悬停时间展示完整日期；实时输出使用首次持久化事件时间，后续分片不刷新时间，历史缺失值不补造。
- 运行中用户补充消息按实际发送时点穿插于过程；后续输出继续排列在后，实时与历史回放顺序一致。展示拆分不修改模型消息或持久化正文，日志不足时保留完整已存内容。
- 同一轮只显示一处运行状态：有执行过程时由过程标题承载处理、停止或等待状态；尚无过程时显示等待提示。主动停止只显示一处中性“已停止”，不显示错误框、原始中断文案或继续按钮；异常中断与真实失败保留原因和恢复入口。过程末尾不单独显示消息日期。历史编辑重新发送成功后以更新后的对话反馈结果，不另弹“历史已更新”通知；删除操作仍提供撤销。
- 执行过程显示本轮记录的开始至结束耗时，进行中可更新；思考耗时使用思考到正文或工具调用的事件边界。缺少边界时不伪造零值；不同轮次和会话隔离计时，结束或失败后停止计时。
- 正文选区提供原生右键复制，编辑区域提供剪切、复制、粘贴、撤销与全选，并按实际可用状态启用；不能用全文复制按钮代替选区复制。模型选择弹层对齐触发按钮，服务标题与模型项分层，搜索、推理设置及管理入口固定，列表独立滚动。
- 用量浮窗以数字、留白和比例条组织累计 token、缓存命中率、上下文余量与文本组成；无余额数据不占位，次要统计和完整明细按需展开、可复制。目标上限可就地调整，改动后才显示保存与取消；沿用全局配置和下一次任务生效边界，不能用新目标改写当前预算。缓存不全、预算未知和未计入图片等影响判断的信息保持可见。目录用于跳转到真实提问，不能混入隐藏上下文或运行内部消息。

### 5.2.1 会话内提问与回执

- 一组问卷保留一个提交边界；默认展开第一题，其他题显示题目与当前答案摘要。选择后不自动跳题，多组请求和不同会话的答案不得混合提交。
- 普通问卷复用 AI 将推荐项放在首位的约定，明确标记并默认选中；用户可改选或填写“其他回答”。默认推荐属于未提交值，必须点击一次“提交回答”才生效，不因超时自动采用。执行批准及拷问执行检查点不能默认推荐或预选授权。
- 题目区可按可用高度滚动，问题数量、采用推荐的数量和统一提交操作保持可达；窄宽时重排操作栏。单选状态用可辨认的标记表达，自定义文字与选项互斥，不能以清空自定义内容为理由重新替用户选回默认项。
- 问卷位于发起它的工具记录下。收到接收确认后，原位置缩为“已提交 N 项回答 · 查看”；完整答案默认折叠，只读且可复制。回执来自实际接收结果，不能从界面默认值补造；确认、结束通知和工具结果乱序到达时不得丢失或重复。整轮结束后，回执随执行过程一起收起；展开后按所属阶段恢复查看入口，最终正文保持可见。待回答或提交失败的问卷保持可操作，不追加模型聊天消息。
- 提交失败保留输入并提供重试；取消或任务结束后展示未提交状态并保留当前输入的查看与复制入口。等待、正在提交和终态明确区分。

### 5.3 输入区

- 只有一层清晰外框，输入控件内部不再叠加第二层装饰边框。
- “+”添加上下文；专家、权限和模型在底部主工具栏就近呈现。已选能力、附件和引用在输入区各自的上下文区域展示，只在确有选择时占位。
- 拷问模式选中时，在底部工具栏的专家入口后显示中性浅底胶囊；左侧“×”取消，文字入口复用模式选择浮层。默认模式不占位，不额外增加说明行；取消保留输入与附件，运行中隐藏取消入口并沿用既有停止规则。胶囊颜色和尺寸读取主题，窄宽时参与工具栏空间分配，不能挤掉模型、发送与停止入口。
- 输入区的对话、附件、技能／连接器与资料库引用共用可换行的标签区域。标签保留类型图标、类型文字与名称，默认使用低饱和浅底色：对话灰蓝、技能／连接器灰紫、资料青绿、附件中性灰；名称保持正文色，状态色不用于分类。颜色通过 `composer_*` 语义 token 随主题更新，不能只靠颜色区分类别。资料标签点击复用管理浮层，悬停提供完整名称和来源；移除可撤销，撤销不得覆盖后来选择或其他会话。选择调整从下次提交生效，已选资料不能表述成已读取或已引用的回答来源。
- “+”选择菜单在一次打开期间保持稳定高度和分类位置，加载中、空列表和长列表不得使悬停目标漂移；右侧列表内部滚动，同源分类复用本次读取结果，关闭后重新读取。技能选择列表按来源隐藏内置能力，保留技能库与用户安装项；能力管理页仍可查看内置能力，隐藏不改变运行时可用能力或已有选择。
- “+”保留 `>` 级联展开，支持悬停、点击和键盘进入子菜单。模式、专家、技能、连接器、对话共用列表行样式：左侧类型图标、名称与简短说明、整行悬停底色；已选项另有勾选标记。输入区专家点击即选中，技能与连接器支持即时多选；结果同步到输入区标签。组合 `@` 选择器原有的暂选／应用边界保持明确。
- 点击浮层及其入口之外的正文、空白或其他控件，关闭整条菜单链；窗口失活也收起。点击子菜单内部保留父层，`Esc` 先关闭当前层。关闭选择器不能清空草稿或撤销已生效的选择。
- 工作目录固定显示在输入框外侧下方，长路径可省略并提供完整提示；切换目录沿用既有会话和运行状态限制。
- 权限入口使用“请求批准 / 完全访问”两行即时选择，保留必要说明，不改变全局保存范围或任务启动时的权限快照规则。模型菜单按服务分组，支持搜索，并按模型实际支持的档位呈现推理选择。
- 输入区只有一个主按钮。空闲时为向上箭头；运行中无待发文字或附件时为停止，有文字、粘贴内容或附件后切换为发送补充，清空后恢复停止。正在停止时禁用并显示明确提示；不接受补充的任务继续提供停止。编辑补充时，“+”中保留“停止当前任务”，停止不清空草稿；右下角已经是停止按钮时隐藏此菜单项，避免重复。回车始终沿用发送行为，不因空输入变为停止。
- 底部主工具栏保持单行，上下文标签允许换行。窄窗口复用已有紧凑布局和长名称省略规则，保留必要操作及完整提示；不要持续缩小字号、点击区域或压缩正文空间。

### 5.4 右侧区域

- 顶部只保留“工作区”入口。“任务”与文件、网页、终端共用标签栏，任务页包含“调用记录、子任务、执行上下文”。
- 任务标签打开后隐藏同栏的任务快捷按钮，切到其他标签时也不重复显示；关闭任务标签后恢复快捷入口。按钮与标签共用既有任务视图状态。
- 点击工具直达参数和结果，点击子任务直达其独立对话，点击文件直达文件；点击“任务”标签返回上次浏览位置，首次进入显示调用记录。具体调用与子任务对话用返回箭头进入各自列表，详情中不重复展示分类栏。
- “对话”固定且不可关闭；其他标签统一带“×”，不添加“隐藏任务”等文案。关闭任务页保留后台运行和浏览状态，可从全部标签或对话中的详情入口再打开；文件、网页、终端沿用既有关闭规则。
- 文件工具栏统一一个保存入口，仅在内容未保存时显示；编辑／预览使用一个切换按钮，重载、复制路径与文件夹定位收进更多菜单。Word/PPT 采用 LibreOffice 页面预览，编辑打开本机应用；组件安装和转换状态可观察、可取消，刷新失败保留现有预览。
- 工作区预览充分利用可用空间，保留原有浮动文件目录、编辑、查找和保存入口。文件目录按钮仅在文件工作区显示，窄标签栏通过省略和横向滚动保留当前标签的关闭操作。
- 文件元信息与编辑操作共用紧凑工具行；更新、错误和恢复入口仍单独可见。Markdown 首次打开默认预览，已有编辑草稿继续保留；HTML 使用页面内可视化编辑，保留原始脚本和样式，预览与保存复用既有安全 DOM 合并。Markdown 阅读预览限制行宽并保留内边距，正文使用界面字体，代码使用等宽字体；源码编辑旁的原生预览沿用相同字号和层级，引用使用其渲染器支持的缩进，不能套用整块代码编辑器样式。主题更新保留阅读位置、选区和编辑草稿。
- 工作区左侧分隔线支持拖动和键盘调整；宽度按会话保留，收起再打开不得丢失未保存编辑。任务直接进入标签页，不使用任务浮层，三项分类始终保留。
- 工作区可展开到左侧导航之外的主区域；展开后固定且不可关闭的“对话”标签显示原有完整消息区和输入区，同一个按钮恢复原分栏及工作区标签。布局切换复用已有控件，不重建消息或输入，也不停止后台任务。
- 新标签页提供“新增页面”。写作页用标题、正文和简洁工具栏组织内容，首次保存命名为工作目录内的 Markdown 文件；草稿随会话恢复，保存是唯一主操作。常用文字格式直接可达，列表、链接和源码入口就近收进更多菜单；失败保留内容并显示恢复入口。
- 网页工具栏按宽度合并或重排，窄宽将缩放收进更多菜单，必要时地址独占一行。控制权切换在同一宽度下不得产生瞬时视口位移；空闲下载区不保留占位。
- Office / HTML 的外部变化只在预览状态区显示“文件已更新”或“页面资源已更新”及“刷新”入口，保留当前画面和阅读位置；后台通知、重复选择当前文件及列表刷新不得重载已显示的同一文件。手动刷新成功后更新展示版本，失败保留已有预览与重试入口；编辑草稿沿用既有冲突保护，不被自动替换。
- 执行上下文分别展示当前选择、本轮提交快照和最近实际模型请求；完整请求按需读取，并校验会话与运行归属。查看历史任务时在各个任务分类和详情页保持可见的历史标识与“返回当前任务”入口；提交与请求标题明确属于该轮，不能暗示属于当前运行。请求不存在或已被替换时说明原因与恢复路径，不能把当前偏好拼装成实际请求；当前轮次变化后清除旧请求展示并丢弃迟到响应。“复制全量”必须复制完整内容。
- 调用详情顶部显示返回箭头、工具名称、真实状态与已记录耗时；工具 ID、时间等放入“运行信息”。参数可折叠，结果区利用剩余空间；两区各保留一个完整复制入口，较长内容可滚动和选择。
- 未选择调用时显示定位入口，不展示空白参数、结果编辑器；选中调用或查看失败详情后显示完整内容。
- 子任务保留独立对话及补充、停止、恢复入口。界面整理不能合并其会话或改变路由。
- 任务页的选中调用、分类、折叠、阅读位置和子任务草稿按会话隔离。界面标签不注册为模型可操作标签，不加入模型上下文；后台更新不切换当前视图。

团队空间、常用任务、设置、能力和资料库共享以上视觉与控件规则，保留各自的任务结构。布局相同不是目标，概念和操作一致才是目标。

常用任务表单按内容、能力、运行设置、定时与消息发送纵向组织；不要把较长的定时或消息配置挤入固定窄侧栏。保存与取消保持可达，已有保存边界和恢复入口不变。

专家和常用任务中的技能选择使用左侧复选框与名称同排的选项，选中项有明确底色，窄窗口改为单列。复选框尺寸不能继承文本输入框的整行宽度。

MCP 服务表单支持选择 JSON 文件或粘贴配置，解析只填入表单，不保存或连接；导入区使用紧凑输入框，多服务解析为可直接点击的列表，不堆叠检测数量、操作指导和重复标签；仍以“保存”为生效边界。导入失败保留原表单和 JSON 输入，认证内容及原始 JSON 不写入持久化表单草稿。

## 6. 控件与操作约定

| 类型 | 使用约定 |
| --- | --- |
| 主按钮 | 当前区域最重要的动作；使用 `primary` 与 `text_inverse` |
| 次按钮 | 同级的辅助动作；弱背景或细边界，避免和主按钮竞争 |
| Ghost / 图标按钮 | 工具栏、局部操作、次要导航；默认轻量，悬停和焦点明确 |
| 危险操作 | 说明影响范围，使用既有确认或可撤销机制；不扩大删除或历史改写范围 |
| 输入与选择 | 标签明确用途；占位提示仅补充必要示例，不能替代标签；辅助说明仅用于必要的格式限制、操作影响或易错点，三者不重复；值、错误和保存边界清楚 |
| 浮层 | 贴近触发入口，支持已有关闭和取消方式；不能重复积累隐藏实例 |
| 折叠详情 | 默认展示任务所需摘要；展开后保留完整内容和复制能力 |
| 通知 | 适合简短结果反馈；需要持续处理的错误在对应任务区域保留恢复入口 |

临时通知 6 秒后自动收起，切换对话或页面清除；IPC 包装前缀在宿主边界统一移除，显示具体原因。需持续处理的错误仍留在对应任务区域。全局通知在当前任务区域底部居中，同一时间只显示一条，宽度随内容增长并受容器约束；已有对话时放在输入框上方，其他页面放在页面底部。中性会话提示使用轻量原位文字，错误和警告保留语义底色及重试、详情等必要入口。能力选择、启动等已有清晰界面结果的操作不再重复弹成功通知。

更新就绪使用独立的侧栏提示条：在线安装包下载并完成校验后，嵌入左侧栏底部、设置入口上方，随布局占位，不覆盖对话和普通通知、不抢焦点。显示版本与“已准备好”，唯一主操作为“重启并更新”，提供可访问的关闭按钮。关闭仅隐藏提示并保留安装包，本次运行同版本不再提示，下次启动重新提示；设置页始终保留安装入口。切页不重建提示，准备安装期间隐藏，未能开始安装时恢复入口。文案可换行，遵循主题和侧栏最小宽度。

按钮文案优先使用“保存、开始、重试、连接、添加”等明确动作。技术细节只有在帮助用户判断或操作时才进入主要流程。

## 7. 状态、连续性与恢复

按受影响场景覆盖以下状态，不为不存在的情况堆砌界面：

| 状态 | 用户应看到什么 |
| --- | --- |
| 空 | 能做什么，以及一个清楚的开始入口 |
| 加载 / 运行 | 正在做什么、已知进度或状态；适用时提供停止或取消 |
| 成功 | 操作结果，以及可查看或继续使用的成果 |
| 警告 | 当前影响与可选行动；不把普通信息渲染成危险 |
| 错误 | 发生了什么、已保留什么、如何重试或继续 |
| 不可用 / 禁用 | 不能操作的原因，以及可达的准备或恢复入口 |
| 悬停 / 焦点 / 选中 | 可辨认的反馈，状态不能只靠颜色表达 |

- 同一任务区域的同一状态就近表达一次；成果或控件变化已清楚反馈成功时，不机械叠加成功标签、横幅和通知。
- 过程摘要仅来自实际事件与真实返回内容；不补写不存在的思考、工具调用、进度或成功状态。
- 停止和失败的提示保持紧凑，避免重复堆叠同一句状态；必须保留实际原因、已完成成果及有效恢复入口。
- 发送后的用户消息、已显示的 AI 正文和已完成成果不能因折叠、重排、切换或失败消失。
- 会话草稿、附件、专家选择和运行身份按会话隔离。切换页面或会话不应擅自停止后台任务。
- 消息渠道顶部按钮只切换查看，启停使用独立的“接收此渠道消息”复选框并统一保存；浏览状态不进入表单草稿。保存成功更新表单基准，旧的初始值不能覆盖刚保存的值。
- 后台操作可按名称、日志与错误搜索，状态筛选与分页使用服务端记录；过程日志只记录真实阶段、状态和时间，旧记录缺失时直接说明。列表响应不能覆盖更新的事件，取消不能把已完成操作改回进行中。
- 表单有明确保存边界；保存失败保留输入，离开未保存状态走统一确认流程。必要时明确区分立即生效的外观选择与需要保存的表单设置。
- 不添加伪造成功或静默替换执行路径的回退。既有重试保持可见、有界，并避免重复消息或重复操作。

## 8. 响应式、键盘与性能

- 小窗口和 Windows 缩放下优先重排、换行、滚动；保证标题、主要操作、输入区和恢复入口可达。
- 图标操作提供提示和可访问名称。键盘焦点清楚，保持既有 Tab、Enter、Esc 和快捷键行为。
- 滚动条可以视觉纤细，但拖动区域要足够。当前对话滚动条视觉宽度 `8`、命中宽度 `14`，不应缩成难以操作的细线。
- 复制和选择应覆盖完整数据。省略只影响呈现，不能截断真实路径、原始参数、结果或保存内容。
- 避免每个字符都触发全文解析、全部控件重建和父级布局。主题、字体和宽度变化时只更新受影响范围。
- 隐藏会话、折叠过程可延迟渲染，但运行、保存与完整内容访问不能依赖控件已经创建。具体边界遵循 [UI 性能准则](UI_PERFORMANCE_PRINCIPLES.md)。

## 9. 实现边界

1. 优先复用 `desktop/src/theme.ts` 的主题映射、作用域 CSS 与现有 React 组件；尺寸和颜色以生效主题及源码为准。
2. 浅色、深色和自定义主题统一更新 CSS 变量。插件订阅宿主主题；禁止全局样式泄漏到独立恢复入口、预览控制和其他插件。
3. AI 主题预览必须隔离、可取消，不修改已保存主题；必要恢复操作不受自定义样式控制。
4. 未发送输入、未保存文件及管理表单属于稳定宿主，按会话／文档／表单 ID 存储；页面卸载不清除。局部弹层、悬停仍由页面持有。
5. 快照与增量经过宿主单一合并入口；不在页面、Controller 和 ref 中维护相互竞争的运行状态。
6. UI 展示状态、插件清单和布局不进入模型聊天历史。发送、保存、历史、运行与恢复改动先阅读对话第一性原则；确需改变模型前缀时按 AGENTS.md 事前确认。

### 9.1 组件与原生表面生命周期

- `HostProvider` 与保存协调器持续存在，`App` 只启动宿主、挂载工作台和恢复入口。默认界面通过内置插件呈现，外部页面／面板使用隔离 iframe。
- 切换插件先等待旧实例的修改结束并保留恢复副本，候选全部就绪后切换；失败保持原选择。异步回调校验实例租约、会话和文件身份。
- 插件、重载、退出和更新共用保存协调；保留恢复副本不能冒充正式保存文件或配置。
- iframe 所在根容器具有明确高度；整体工作台、页面与局部面板分别使用对应的布局边界，不能依赖 iframe 默认尺寸。
- 原生 `BrowserWindow`、`WebContentsView`、终端进程和订阅由 Electron／Python 宿主管理；React 卸载只取消对应视图订阅，不重启后台任务。
- 回收前移除事件监听并使旧实例失效；原生网页表面在面板隐藏、插件切换及弹层显示时由宿主更新边界和可见性，避免覆盖恢复操作。
- 界面生命周期通过当前 Electron 宿主和 React 组件验收；历史实现通过 Git 查阅。

## 10. 交付与验收

验收以代表性用户任务为主，而不是逐个控件看起来是否漂亮。根据改动范围选择以下检查：

- 首次进入能找到开始入口；正常操作能完成并确认结果。
- 逐项检查次要标签与描述：删除后若仍能理解分组、选择和下一步，且不损失第 2 节要求的必要信息与可访问性，优先删除。
- 输入、草稿和已完成内容在切换、取消、失败后保留。
- 对话展示改动同时覆盖实时插入、历史首次加载与重载、连续切换及详情展开。按范围加入纯附件、多引用和专家切换，检查身份标题唯一且历史身份正确，不能只验证新对话中的静态样例。
- 空、加载、运行、失败、不可用和焦点状态有明确表达。
- 长标题、长路径、多引用和长结果不挤掉主要操作，完整信息可访问。
- 消息滚动不移动固定标题和输入区；查看历史时保留阅读位置。
- 右侧面板展开后正文和控件不重叠，浮层不越出可用区域。
- 浅色、深色、小窗口、Windows 高 DPI 和主题预览取消覆盖受影响场景；长原文检查末行、选择和复制完整性，不能只看控件外框是否完整。
- 涉及挂载、切换或销毁时，检查 Electron 窗口／网页表面数量、旧实例失效与订阅回收；候选失败不得卸载当前界面，默认截图不能代替失败与迟到回调验证。
- 流式输出、输入、滚动和停止操作保持及时响应。
- UI/UX 改动未改变原有业务结果、消息可靠性、权限或会话隔离。

复用当前测试和截图脚本，检查与变更相称的范围；不要为低风险样式改动编写只复述实现的测试。必要检查通过后，除非出现新改动或疑点，不反复扩大测试。

记录实际平台、Windows 显示缩放、Chromium 缩放和窗口尺寸。页面 zoom 与系统 DPI 是不同条件；模拟缩放和离屏截图不能替代 Windows 原生窗口验收。
