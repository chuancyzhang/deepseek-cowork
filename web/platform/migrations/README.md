# 数据库结构

在部署文件夹内运行 `python -m server migrate`。当前结构版本为 2，基础表定义在 `server/database.py`，团队空间表定义在 `server/team_space_tables.py`，`platform.schema_version` 记录已完成版本。

启动也检查平台标识与结构版本；未知版本在执行 DDL 前立即失败，不自动猜测、删除或重建数据。版本 1 包含独立管理员、初始化、员工数据库凭据和登录入口表，已有成员或认证来源时不会开放初始化。

版本 1 → 2 在单个数据库事务内增加独立的团队空间、成员、邀请、计划、留言、动态、文件夹、上传、资产、资产修订、成果、快照和幂等操作表，然后更新结构版本。基础账号、授权、提问和发行记录不重写。重复迁移无副作用；未来已有列的修改必须增加明确迁移，不能依赖 `create_all`。

升级前停止应用写入，备份排除 `questions` 正文的业务数据库、完整文件卷及加密密钥。回滚使用升级前匹配的数据库与文件备份；不把结构版本号手动改回 1。恢复版本 2 后执行 `python -m server verify-space-files`，该命令逐个核对已发布文件的大小和 SHA-256，失败返回非零退出码，输出仅含文件 ID 和错误类别。启动不会把中断上传当成已发布文件。

同一数据库只服务一个 `platform_id`。不同企业必须使用独立数据库、加密密钥和文件卷。正式环境仅支持 PostgreSQL。
